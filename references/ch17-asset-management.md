# 第17章 资产管理与复用（长篇/多集项目必用）

> 本章适用于一部漫剧多集制作、角色/场景/道具反复出场的项目。单集独立项目可跳过。

## 17.1 核心原则

### 17.1.1 资产描述只从正文提取

角色、场景、道具、生物的具体描述（外貌、服装、法器、环境细节等），**只能从小说正文中提取**，禁止从大纲编造。大纲只提供角色名、场景名和剧情走向，不提供具体描述。

正文中没有明确描述的资产，标注"待正文补充"，不擅自编造。

### 17.1.2 存角色核心描述，不存完整提示词

资产库里存的是**角色核心描述**（不变量），不是生成三视图/多视图时用的完整提示词。

**完整提示词**里包含布局规范（如"面部特写+无头三视图""正面侧面背面""中性站姿""空白背景"）和场景/光线/动作变量，这些是生成资产图专用的，写分镜时会干扰，不存进资产库。

**角色核心描述**只保留跨镜头不变的内容：
- 骨相（脸型、下颌、三庭五眼特征）
- 五官（眼型、鼻、唇、眉）
- 发型发色、发冠发饰
- 服装（该造型的服装细节、面料、纹饰）
- 随身法器/道具（该造型携带的）
- 标志性特征（疤痕、纹身、灵力纹路、胎记）
- 灵光色、肤质（如玉质通透）
- 气质

**去掉**：布局规范、场景、光线、动作、构图、相机角度。

### 17.1.3 只增不删，版本管理

资产库**只增加，不物理删除**。原因：
- 同一人物多造型（日常/战斗/受伤/少年回忆）都可能在后续剧情中用到（闪回、回忆、不同时间线）
- 删除会丢失历史，后面需要时找不回来

更新规则：
- **新造型/新资产**：增加新记录
- **同造型修正**（骨相参数改错、描述补充）：用版本号 v1→v2，旧版本保留可回滚
- **不再使用的资产**（角色死亡后不再出场、场景废弃）：标记`已废弃`，不删除，保留记录可追溯

## 17.2 编号体系

### 17.2.1 类型前缀

| 前缀 | 类型 | 说明 |
|---|---|---|
| R-xxx | 角色 Role | 人物 |
| P-xxx | 道具 Prop | 武器、法器、物品 |
| S-xxx | 场景 Scene | 地点、环境 |
| C-xxx | 生物 Creature | 妖兽、灵兽、动物 |

编号从 001 开始，按首次出场顺序递增。

### 17.2.2 造型后缀

同一角色/生物的不同造型用大写字母后缀：
- `R-001-A`：默认造型（首次出场时的造型）
- `R-001-B`：第二套造型（如战斗服、下山历练装）
- `R-001-C`：第三套造型（如受伤状态、入魔后、黑化）

造型后缀按出现顺序分配。每套造型有独立的核心描述（骨相五官不变，服装/法器/灵光色/气质可能变）。

### 17.2.3 版本号

同造型的描述修正用版本号：
- `R-001-A-v1`：初始版本
- `R-001-A-v2`：修正后版本（骨相参数调整、描述补充等）

写分镜时默认引用最新版本，需要旧版本时显式指定。

## 17.3 资产记录字段

每条资产记录包含以下字段：

```
编号：R-001-A
名称：凌渊
类型：角色
造型版本：前期默认造型（第1-12集·宗门日常）
角色核心描述：二十岁男性，鹅蛋脸长脸，丹凤眼，黑发高束玉冠，
  月白锦袍银纹，腰悬青锋剑，左手背旧疤，气质清冷孤傲，
  肤色玉质通透，周身淡蓝灵光。
首次出场：第1集
状态：已锁定（v1）
备注：骨相五官为全剧不变量；青锋剑对应 P-014
```

字段说明：
- **编号**：类型前缀+序号+造型后缀
- **名称**：资产名称
- **类型**：角色/道具/场景/生物
- **造型版本**：该造型适用的剧情范围（如"第1-12集·宗门日常"）
- **角色核心描述**：从正文提取的不变量描述（场景/道具/生物同理，写核心特征）
- **首次出场**：首次出现的集数
- **状态**：待补充/已锁定(v1)/已更新(v2)/已废弃
- **备注**：关联资产、禁忌、特殊说明

## 17.4 复用流程

### 17.4.1 项目开始

1. 读取项目资产库文件（如 `asset-registry.md`），如果不存在则按模板新建
2. 确认制作范围（如"第1-100集"）和制作模式（一章一集）

### 17.4.2 每集制作前

1. 读取当前集小说正文
2. 从正文中提取本集出现的所有资产（角色/道具/场景/生物）
3. 对比资产库：
   - **已有的资产**：直接复用，写分镜时引用编号+核心描述
   - **已有角色但新造型**：增加新造型记录（如 R-001-B）
   - **完全新增的资产**：标记"需制作"，从正文提取核心描述
4. 只制作"需制作"的资产，不重复生产已有资产

### 17.4.3 每集制作后

1. 新制作的资产写入资产库（增加新记录或新版本）
2. 更新已有资产的首次出场/状态等字段
3. 保存资产库文件

## 17.5 写分镜时的资产引用

写分镜 AI 提示词时，人物锚字段直接引用资产库的核心描述：

```
[人物锚：R-001-B 核心描述全文]
+ [动作：负手而立，缓缓抬头]
+ [场景：竹林深处，雾气弥漫]
+ [光线：晨光穿透竹叶]
+ [运镜：中景缓推]
= 最终分镜提示词
```

禁止在分镜提示词中出现资产编号（如"R-001"），必须展开为核心描述。资产编号只在内部和资产库中使用。

## 17.6 大纲使用边界（强制）

### 17.6.1 大纲的定位

作者已有小说正文，且持续更新中。大纲仅作为以下用途的参考：
- 章节走向和发展趋势
- 当前章在全剧中的位置
- 前后剧情衔接
- 主要角色的弧线方向（仅作理解参考）
- 关键伏笔的埋收位置（仅作提醒）

### 17.6.2 禁止事项

- **禁止以大纲为基础创作正文里没有的剧情、台词、细节**
- **禁止因为大纲里写了后续剧情，就在当前章提前加入正文没有的暗示或铺垫**
- **禁止从大纲编造角色外貌、服装、场景描述**（这些只能从正文提取）
- 做某一集时，该集内容以该集小说正文为唯一依据，大纲只用于理解上下文位置

### 17.6.3 正文优先

正文中的描述与大纲不一致时，**以正文为准**。大纲可能滞后于正文更新，或存在概括偏差。

## 17.7 逐章制作工作流

适用于"一章一集、做一章发一章"的连载项目：

1. **项目初始化**：读取大纲，建资产库编号骨架（角色名/场景名占位，描述留空），提取关键伏笔清单，确认制作范围
2. **逐集制作**：
   - 用户发送该集小说正文
   - 从正文提取本集资产，对比资产库，制作新增资产
   - 参考大纲（仅作走向/衔接参考）+ 资产库 + 该集正文，制作分镜
   - 新资产写入资产库
   - 交付该集分镜
3. **循环**：用户发送下一集正文，重复步骤2

**注意**：项目初始化时不做完整蓝图，不创作正文未覆盖的内容。资产库描述全部从逐集正文中提取。
